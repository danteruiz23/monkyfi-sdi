# Decisions

One line per decision. Newest at the bottom. Items still open are listed in `docs/SPEC.md`, section 17.

| # | Date | Decision | Reason |
|---|---|---|---|
| D01 | 2026-11-09 | MVP products are EPL (Ethernet Private Line) and wavelength. | A critical-field checklist needs a concrete product; wavelength supports a hyperscaler prospect. |
| D02 | 2026-11-09 | The demo is defined by UC02, UC03, UC04 and UC06. UC05 and UC08 are built but do not block the demo. UC01, UC07, UC09 and UC10 come later. | Six P0 use cases are too many for a one-person team; these four are the path an SDM recognizes in 10 minutes. |
| D03 | 2026-11-09 | The schema includes `project` and `shared_resource` from Phase 1. | A multi-circuit wavelength project can be shown in the demo without redesigning the database later. |
| D04 | 2026-11-09 | Python for ingestion, extraction, validators and evals; TypeScript for the web view and API on Vercel (Phase 8); rules live in JSON. | Each language where it is strongest; JSON rules are readable by both. |
| D05 | 2026-11-09 | Database is Supabase (Postgres) with RLS for tenant segregation. | Schemas become migrations; RLS implements the segregation required by RF10. |
| D06 | 2026-11-09 | Agent model is Muse Spark 1.1 (Meta Model API, OpenAI SDK-compatible) for development, Gemini as second model for comparison, behind a swappable provider layer. | Changing model must not rewrite the agent; it only forces an eval re-run. |
| D07 | 2026-11-09 | English by default everywhere (docs, code, comments, UI, agent communications), with a language setting to switch UI and communications to Spanish per user or per audience. i18n from the start; no hardcoded UI strings. | Carriers and hyperscalers work in English; LATAM audiences need Spanish without a retrofit. |
| D08 | 2026-11-09 | Test data is synthetic only, generated by a script that seeds defects so golden labels are known by construction. | There is no pilot carrier and no historical orders; seeded defects remove manual labeling. |
| D09 | 2026-11-09 | Source documents are renamed to `docs/PRD.md`, `docs/REVIEW.md` and `docs/DEFINITIONS.md`, content unchanged. | Stable names that the SPEC, CLAUDE.md and prompts can reference. |
| D10 | 2026-11-09 | Repository adds `web/`, `supabase/migrations/`, `locales/`, `prompts/` and `src/providers/` to the structure in the review. | The review left code folders open until the language was decided; these follow from D04–D07 and improvement 11. |
| D11 | 2026-11-09 | Phase 4 includes a minimal slice of UC07: one blocked `shared_resource` flags every linked order. The consolidated view and de-duplicated requests stay post-demo. | Demo step 6 and mandatory case 7 need it, while full UC07 is deferred by D02. |
| D12 | 2026-11-09 | Phase 6 is UC08 with gates G3 and G4 only. G5, hypercare (UC09) and closure (UC10) are post-demo. | Aligns the review's Phase 6 with D02. |
| D13 | 2026-11-09 | Gate assignment: G1 in Phase 3, G2 in Phase 4, G3–G4 in Phase 6; G0 is post-demo with UC01. | G0 is the presales handover and depends on UC01; G2 had no phase. |
| D14 | 2026-11-09 | Dataset is 44 orders: 36 in the dev/eval split (24 dev, 12 eval) plus 8 adversarial reported separately. | Reconciles the 30–40 in the review, the table in the definitions and the 24 + 12 split. |
| D15 | 2026-11-09 | Schema adds `evidence` and `supplier` (Proposed fields). Actions are folded into `finding`, site data stays as `endpoint` fields, `hypercare_event` is deferred. | UC08 needs evidence and UC05 needs supplier; the rest is not needed before the demo. |
| D16 | 2026-11-09 | Segregation at two levels: RLS by tenant, tested with a second synthetic tenant, plus customer-level scoping in validators and the audience filter. | With one fictional carrier tenant RLS is never exercised, and the "wrong customer" case is customer-level. |
| D17 | 2026-11-09 | SPEC and DECISIONS refer to sales prospects generically ("a hyperscaler prospect"); the source documents stay as written. | Consistent with the rule of no real company names for customers. |
| D18 | 2026-11-09 | `docs/SPEC.md` v1.0 approved; Phase 0 is Done. Items labeled Proposed in the SPEC remain proposals. | Phase 0 exit criterion met. |
| D19 | 2026-11-09 | Critical fields (SPEC 8.4) validated by Dante with additions. Both products: authorized signature, carrier circuit ID, cross-connect responsibility and data center operator, site access details and MMR, contacts by role, deemed-acceptance terms, and "FOC date" as a synonym of committed date. EPL: port speed and CIR as separate fields, fiber type and optic wavelength, L2CP transparency (conditional). Wavelength: optic reach, FEC when OTN, route diversity with explicit reference and evidence (no reference is a finding), latency with definition and method, protection switching time when protected. Decided by Dante. | G1 cannot be evaluated without the signature fields; the rest are what delivery needs to provision and accept without rework. |
| D20 | 2026-11-09 | Severity (SPEC 8.3) validated by Dante with changes: critical explicitly includes another customer's data in the package and a missing or unauthorized signature; high = puts a committed date at risk, medium if only a forecast date is affected; when unsure, assign the higher severity and escalate to the data owner, and the agent never lowers a severity on its own. Decided by Dante. | Matches how a carrier classifies; ties severity to commitments rather than estimates. |
| D21 | 2026-11-09 | Demo script has two variants over the same dataset: "carrier" (the original 6 steps) and "hyperscaler" (opens with the 3-wavelength project, route diversity and the shared blocker, then steps 1–5). No extra build scope. Decided by Dante. | Lets the same demo lead with what each audience cares about. |
| D22 | 2026-11-09 | Every foreign key pointing to `service_order` is named `service_order_id`, not `order_id`. Decided by Dante. | Consistency with the table name before migrations are written. |
| D23 | 2026-11-09 | Gemini as comparison model is Proposed, not decided; Dante decides before Phase 2. The Phase 2 two-provider exit criterion applies only if Gemini is kept. Amends D06; Muse Spark 1.1 via Meta Model API remains the agent model. Decided by Dante. | The second model is optional and should not gate Phase 2. |
| D24 | 2026-11-09 | Phase 1 approved to start. Two example orders (one EPL, one wavelength) are reviewed by Dante before the rest of the dataset is generated. Decided by Dante. | Review effort goes into realism before 44 orders are produced. |
| D25 | 2026-11-09 | Handoff interface is per endpoint, not per order: interface type (or client interface), optic, optic reach and connector are stored for the A end and the Z end, which can differ. The dataset has at least 3 orders with different A and Z handoffs and at least 1 where that difference is the defect. Fiber type and optic wavelength (EPL) were moved with them because they follow the optic (Proposed). Decided by Dante. | One end can be in a colocation facility and the other at a customer site. |
| D26 | 2026-11-09 | Only the carrier's commitment to the customer is the order's committed date. A supplier's FOC stays on the supplier dependency. Decided by Dante. | A supplier commitment supports a forecast; it is not a promise to the customer. |
| D27 | 2026-11-09 | Route diversity required without a reference circuit is a critical finding. Decided by Dante. | The design cannot be validated and the commitment cannot be evidenced. |
| D28 | 2026-11-09 | G1 passes when critical fields are consistent across authoritative sources with no missing or contradictory values. G1 must not require `verified`. Written in SPEC section 6 and `rules/gates.json`, with tests. Decided by Dante. | `verified` belongs to the data owner; requiring it would block every order at intake. |
| D29 | 2026-11-09 | The per-field missing-field severities in `rules/fields.*.json` are accepted as defaults. The full severity table is part of the 6-order sample review. Decided by Dante. | Defaults are enough to build on; they stay configurable per rule. |
